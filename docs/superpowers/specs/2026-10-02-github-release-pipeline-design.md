# Спецификация: релизный пайплайн GitHub Actions для Windows и Linux

Дата: 2026-10-02
Статус: утверждён к реализации
Область: `.github/workflows/`, `src-tauri/tauri.conf.json`, документация

## 1. Контекст

Планы 1–3 превратили Handy в офлайн-приложение с одной встроенной моделью
GigaAM v3, русским интерфейсом и брендингом `ХЭНДИ`. Локально на Windows
собран неподписанный NSIS-установщик на 165,4 МБ, в состав которого входит
`resources/models/giga-am-v3-int8/model.int8.onnx`.

Осталось собрать этот же продукт в GitHub Actions и выложить в релиз.
Репозиторий — форк `metalmon/Handy`, версия приложения `0.9.7`.

Существующий пайплайн upstream непригоден для форка по трём причинам.

1. **Подпись.** `src-tauri/tauri.conf.json:74` задаёт
   `signCommand: trusted-signing-cli ...` (Azure Trusted Signing). Без
   секретов эта команда не найдена и сборка Windows падает с
   `program not found`. Локально это воспроизведено; обходной путь с
   временным `--config` описан в `BUILD.md:306-321`.
2. **Матрица.** `release.yml:49-69` и `main-build.yml:22-43` строят семь
   целей: macOS ARM и Intel, Ubuntu 22.04 (deb), Ubuntu 24.04
   (appimage, rpm), Ubuntu ARM64, Windows x64 и ARM64.
3. **Публикация.** Джоб `create-release` создаёт черновик, а джоба,
   который переводит его в опубликованный, в пайплайне нет. Релиз навсегда
   остаётся черновиком и не виден пользователям.

Дополнительно: `TAURI_SIGNING_PRIVATE_KEY` в `build.yml:529-530` стал
мёртвым, так как апдейтер удалён и `createUpdaterArtifacts` не задано.

## 2. Цели

- Релизный воркфлоу, который по одному запуску публикует в GitHub Release
  установщик Windows и пакеты Linux.
- Совместимость с **Astra Linux SE 1.8** (deb) и **РЕДОС 8** (rpm).
- Возможность перезапустить воркфлоу и перезаписать ассеты существующего
  релиза без бампа версии.
- Проверка в CI того, что в пакет попала встроенная модель, и того, что
  требуемая версия glibc не превышает базу целевых дистрибутивов.

## 3. Не-цели

- macOS, ARM64 и AppImage в релизе не собираются.
- Подпись артефактов: решение владельца — сборка без подписи.
- Бамп версии: остаётся `0.9.7`, тег `v0.9.7` переиспользуется.
- Кеширование 215 МБ модели в CI.
- Любые изменения рантайма, UI или модели.

## 4. Целевые дистрибутивы и glibc

| Дистрибутив | База | glibc | Формат |
|---|---|---|---|
| Astra Linux CE 2.12 «Орёл» | Debian 12 | 2.36 | deb |
| **Astra Linux SE 1.8** | Debian 12 | **2.36** | **deb** |
| Astra Linux SE 1.7 | Debian 10 | 2.28 | deb |
| **РЕДОС 8** | RHEL-подобная, DNF | **2.36** | **rpm** |
| РЕДОС 7.3 | RHEL-подобная | 2.28 | rpm |

Цели пользователя — SE 1.8 и РЕДОС 8, обе на glibc 2.36.

Раннеры GitHub дают: `ubuntu-22.04` — glibc 2.35, `ubuntu-24.04` — 2.39.

Следствия:

- Пакет, собранный на `ubuntu-22.04`, требует не выше `GLIBC_2.35` и потому
  гарантированно работает на обеих целях (2.35 < 2.36).
- Пакет, собранный на `ubuntu-24.04`, собран против glibc 2.39 и на РЕДОС 8
  (2.36) может не запуститься. Upstream собирает rpm именно там
  (`release.yml:58-60`) — для наших целей это неприемлемо.

## 5. Матрица сборки

| runner | args | target | артефакты |
|---|---|---|---|
| `ubuntu-22.04` | `--bundles deb,rpm` | `x86_64-unknown-linux-gnu` | `.deb`, `.rpm` |
| `windows-latest` | `""` | `x86_64-pc-windows-msvc` | NSIS `.exe`, MSI `.msi` |

Изменение против upstream: rpm переезжает с `ubuntu-24.04` на
`ubuntu-22.04`, а deb и rpm собираются одним джобом. Побочная выгода — один
Linux-джоб вместо двух.

Почему deb остаётся на 22.04: собранный на ней пакет тянет более старый glibc
и работает на более широком круге дистрибутивов, включая обе цели.

Windows собирает и NSIS, и MSI, потому что аудит в `build.yml:876-895`
требует оба типа установщика. NSIS показывает `ХЭНДИ` (`DISPLAYNAME`),
MSI — ASCII `Handy` из-за ограничений WiX; расхождение описано в `BUILD.md`.

## 6. Жизненный цикл релиза

### 6.1 Идемпотентный `ensure-release`

Джоб `create-release` переименовывается в `ensure-release`:

1. Читает версию из `src-tauri/tauri.conf.json`, строит тег `v<version>`.
2. Ищет релиз по `tag_name` **через список релизов с пагинацией**, а не через
   `GET /releases/tags/{tag}`: последний не возвращает черновики, поэтому при
   перерелизе нашёл бы пустоту.
3. Если релиз найден — удаляет все его ассеты. Без этого повторная загрузка
   файла с тем же именем падает с 422.
4. Если не найден — создаёт новый черновик с автосгенерированными заметками.
5. В обоих случаях отдаёт `release-id` джобу сборки.

### 6.2 Матрица сборки

`fail-fast: false` (одна упавшая цель не отменяет остальные),
`sign-binaries: false`, `upload-artifacts: false`, `no-cache: true`
(сборочные релизы никогда не тянут кеш Rust — устаревшая нативная
библиотека не должна попасть в поставляемый артефакт).

### 6.3 Публикация

Новый джоб `publish-release` с `needs: publish-tauri` переводит черновик в
опубликованный и печатает ссылку. Пока хоть одна цель не зелёная, джоб не
запускается: автоматическая публикация есть, но она не может выпустить
битую сборку.

На воркфлоу вешается
`concurrency: { group: release, cancel-in-progress: false }`, чтобы два
одновременных запуска не вытаскивали ассеты друг у друга.

Итог: перезапуск воркфлоу перезаписывает ассеты релиза `v0.9.7` и
публикует его заново. Бамп версии не требуется.

## 7. Правки `build.yml`

### 7.1 Снятие подписи

- Удалить шаги установки и кеширования `trusted-signing-cli`.
- Удалить обвязку `AZURE_*` и `TAURI_SIGNING_PRIVATE_KEY` из окружения
  `tauri-apps/tauri-action`.
- Удалить `signCommand` из `src-tauri/tauri.conf.json:74`.

Это чинит сборку Windows во всех четырёх вызывающих воркфлоу
(`release.yml:76`, `main-build.yml:51`, `build-test.yml:40`,
`pr-test-build.yml:46` — во всех `sign-binaries: true`) и попутно локальную
сборку, которая требовала обходного `--config` из `BUILD.md:306-321`.

### 7.2 Сохранённые ветки

Платформенные блоки macOS и ARM не трогаем: они обёрнуты в
`if: contains(inputs.platform, ...)`, безвредны и оставляют возможность
вернуть macOS позже. Стричь их — риск сломать `build-test.yml` и
`pr-test-build.yml` без выигрыша.

### 7.3 Новые проверки

**Windows** (`build.yml:795-895`). После тихой установки NSIS и MSI
запускается `handy.exe --list-models --json`; требуется элемент с
`id == "gigaam-v3-e2e-ctc"` и `is_downloaded == true`. Проверка опирается на
наблюдаемое поведение программы, а не на угаданный путь: команда реализована
в `cli.rs:54` и `lib.rs:437` и печатает `ModelInfo[]` с флагом
`is_downloaded`. Локально на собранном бинаре проверено: вывод содержит
`"source": { "Bundled": { "dir_name": "giga-am-v3-int8" } }` и
`"is_downloaded": true`.

**Linux** (`build.yml:613-793`). В листинг deb и rpm добавляется требование
файла `giga-am-v3-int8/model.int8.onnx`. На собранном `handy` выполняется
`objdump -T`, из вывода выбирается максимальная требуемая версия символа
`GLIBC_x.y`; сборка падает, если она выше **2.35**.

Вторая проверка существенна: она превращает совместимость с РЕДОС 8 из
надежды в утверждение, проверяемое машиной, и ловит ситуацию, когда раннер
молча поднимает glibc выше базы целевых дистрибутивов.

### 7.4 Матрицы тестовых воркфлоу

`build-test.yml` и `pr-test-build.yml` сокращаются до тех же двух целей,
что и релиз: форк не должен платить за macOS и ARM на каждом PR.
`main-build.yml` — аналогично.

## 9. Верификация и её границы

Проверяемо локально и в CI:

- `bun run build`, `bun run lint`, `bunx tsc --noEmit`, `cargo test -p handy`.
- Первый прогон релизного воркфлоу: три проверки из 7.3 должны пройти на
  реальных ранерах, что впервые проверит содержимое deb и rpm.

Не проверяемо без доступа к целевым системам:

- Установка и запуск на Astra Linux SE 1.8 и РЕДОС 8. Локальная машина —
  только Windows; это ручная проверка владельца на обеих системах.
- Разрешимость зависимости `webkit2gtk4.1` в репозитории РЕДОС 8. Если
  пакета нет, rpm не установится ни при какой сборке: придётся либо
  подключать репозиторий, либо отказаться от rpm в пользу AppImage.
  Проверяется командой `dnf list webkit2gtk4.1` на РЕДОС 8.

## 10. Риски

| Риск | Что делаем |
|---|---|
| `webkit2gtk4.1` отсутствует в РЕДОС 8 | Проверка на целевой системе до релиза; запасной вариант — AppImage |
| Модель (~215 МБ) качается в каждом из джобов | Принято: два джоба, кеш не добавляем |
| glibc-ассерт даёт ложное срабатывание | Ассерт проверяет требуемые символы, а не версию раннера; при отладке печатается полный список |
| Репозиторий с приватными секретами для подписи | Секреты не нужны, обращений к ним не остаётся |

## 11. Критерии приёмки

1. Воркфлоу `release.yml` запускается вручную и публикует релиз с четырьмя
   ассетами: NSIS `.exe`, MSI `.msi`, `.deb`, `.rpm`.
2. Повторный запуск перезаписывает ассеты того же тега `v0.9.7` и
   публикует релиз заново.
3. При падении любой цели релиз остаётся черновиком.
4. Аудит Windows подтверждает `is_downloaded == true` для
   `gigaam-v3-e2e-ctc` в обеих установках.
5. Аудит Linux подтверждает наличие `model.int8.onnx` в deb и rpm и
   максимальную требуемую версию `GLIBC_2.35`.
6. Сборка Windows проходит без секретов и без обходных конфигов.
